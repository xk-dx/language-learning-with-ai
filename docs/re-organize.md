可以，我会在 Gemini 那套“四流程”的基础上做贴合项目实际的版本。总体上我建议不要把它推翻重来，而是保留它的心智模型：

**配置与入门 → 建词表/收集词 → 学习与测验 → 看报告再复习**

但需要把原项目里已经实现的 Agent、RAG、识图、阅读、测验、进度这些能力重新归位，避免继续作为“技术展示型入口”堆在一起。

> 后续实现待办、技术债和暂缓事项统一记录在 [`docs/todo.md`](./todo.md)。本文档负责描述目标交互流程，TODO 文档负责跟踪落地进度和实现差距。

**新的全局架构**
左侧固定导航栏保留 Gemini 的五个主入口：

```text
┌────────────────────┐
│ WordForge          │
│                    │
│  仪表盘 Dashboard  │

│  学习报告 Progress │

```

我建议把原来的顶部 Tab 全部取消，改为左侧导航。左侧导航类似手机 App 的底部选项栏：永远告诉用户“我现在在哪个任务域里”。原来的 `Overview` 被 `Dashboard` 替代，原来的 `Lists` 变成 `Vocab` 下的大厅和工作台，原来的 `Learn + Quiz + Agent` 大部分合并到 `Study`，原来的 `Progress` 保留但重新组织，`Settings` 是新增重点页面。

## 流程一：新手破冰与系统配置流程

目标：解决“第一次打开不知道干什么”和“API Key/模型配置无处安放”的问题。

### 1. 快速上手弹窗 Onboarding Modal

对应步骤：新用户首次打开网页。

这个不建议做成常驻页面，而是首次进入时覆盖在 Dashboard 上的居中弹窗。

```text
┌──────────────────────────────┐
│ 从一个真实场景开始学英语       │
│                              │
│ Example：咖啡店聊天           │
│                              │
│ 1. 先定场景                  │
│ 2. 再补语料                  │
│ 3. 最后放进练习              │
│                              │
│ [稍后配置] [配置 AI 能力]      │
└──────────────────────────────┘
```

弹窗实际落地时分两步，但内容和原先设想相比做了调整：

1. 第一步不再展示所有功能，而是用一个典型场景解释产品心智：用户想练“咖啡店聊天”，于是创建一个围绕“朋友见面、点单、闲聊”的词表；系统再围绕这个语境补全释义、例句、发现新词，并把词放进卡片、短文、测验和口语练习里。这样用户先理解 WordForge 的特色是“针对特定场景和特定语境做定向提升”。
2. 第二步再自然进入配置：AI 补全释义、生成短文、场景口语陪练都依赖后端模型服务，所以先确认 API Key、Base URL、默认模型和 Pexels Key 等配置。这里的配置页面不再作为孤立的系统表单出现，而是作为“让场景学习真正跑起来”的准备步骤。

贴合项目实际的处理方式：

- 当前后端 API Key 是通过 `.env` 读取的，不是前端直接控制。
- 所以设置页可以先做“配置状态展示 + 本地配置表单 + 测试连接”。
- 如果要让前端填写后真正生效，需要后端新增保存配置接口；这是小型新增功能，但要注意本地安全。
- 当前版本已经按上述思路重写了 Onboarding：第一页围绕“咖啡店聊天”讲清楚场景化学习，第二页解释 AI 配置为什么和这个学习流程相关。

### 2. 系统设置页 Settings Page

对应步骤：日常修改配置、管理本地数据。

入口：左侧导航底部 `系统设置`。

页面布局：

```text
┌───────────────┬──────────────────────────────┐
│ 设置菜单       │ 设置内容                      │
│               │                              │
│ 大模型配置     │ API Key 输入框                │
│ 图片服务配置   │ Base URL 输入框               │
│ 学习偏好       │ 默认模型选择                  │
│ 数据管理       │ [测试连接]                    │
│ 关于项目       │                              │
└───────────────┴──────────────────────────────┘
```

建议设置分区：

1. **大模型配置**
   - API Key
   - Base URL，例如 DeepSeek/OpenAI compatible endpoint
   - 默认模型
   - 测试连接按钮，对应后端 `/api/config` 或新增 `/api/test-config`

2. **图片服务配置**
   - Pexels API Key
   - 用于单词详情配图

3. **学习偏好**
   - 默认学习词表
   - 默认练习模式：卡片 / 阅读 / 混合测验
   - 语音朗读开关
   - 默认语音语言

4. **数据管理**
   - 恢复示例数据，对应原来的“恢复”
   - 清空本地学习数据
   - 导入/导出词表 JSON，可以酌情新增，适合本地网页项目展示

这个页面吸收原 1-6、78-84 里和配置相关的功能。

## 流程二：词表管理与 AI 语料构建流程

目标：把“创建词表、加词、AI 生成、PDF 提取、识图加词”统一成“收集与整理词汇”的任务流。

原来这些功能散落在词表页和 Agent 页，现在建议全部归入 `我的词库 Vocab`。

### 1. 词表大厅页 My Word Lists

对应步骤：查看已有词表、创建新词表、选择一个词表进入工作台。

入口：左侧导航 `我的词库`。

页面布局：

```text
页面顶部：
[ 我的词库 ]                         [+ 创建新词表]

主体：
┌────────────┐ ┌────────────┐ ┌────────────┐
│ 旅行文化    │ │ 咖啡店聊天  │ │ AI 产品讨论 │
│ 12 个单词   │ │ 8 个单词    │ │ 15 个单词   │
│ 掌握度 62%  │ │ 掌握度 74%  │ │ 掌握度 55%  │
│ █████░░░   │ │ ██████░░   │ │ ████░░░░   │
└────────────┘ └────────────┘ └────────────┘
```

交互：

- 点击词表卡片进入“词表工作台”。
- `+ 创建新词表` 打开轻量弹窗，而不是把新建表单常驻在页面左侧。
- 删除词表放到卡片右上角更多菜单里，降低误触风险。

保留原功能：词表列表、创建词表、删除词表、词表掌握度展示。

### 2. 词表工作台页 List Workspace

对应步骤：管理某个具体词表，添加、生成、查看、删除单词。

页面布局建议：

```text
顶部：
← 返回词库    旅行文化        12 个单词 · 平均掌握度 62%

主体：
┌─────────────────────────────┬──────────────────────┐
│ 单词列表                     │ 快捷操作              │
│                             │                      │
│ search...                   │ 手动添加单词          │
│                             │ [word]               │
│ check-in      办理入住       │ [meaning 可空]        │
│ boarding      登机           │ [加入词表]            │
│ suitcase      行李箱         │                      │
│                             │ AI 发现新单词         │
│                             │ 数量 / 难度 / 生成     │
│                             │                      │
│                             │ 资料导入              │
│                             │ 上传 PDF / 提取生词    │
│                             │                      │
│                             │ 图片识词              │
│                             │ 上传图片发现物体       │
└─────────────────────────────┴──────────────────────┘
```

这里我建议比 Gemini 稍微扩展右侧操作区，因为项目里确实有三种“收集词”的方式：

1. 手动添加单词
2. AI 按场景生成候选词
3. PDF 提取生词
4. 识图学词加入词表

这些本质上都是“往词表里收集词”，不应该藏在 Agent 里。

### 3. 单词详情抽屉 Word Detail Drawer

对应步骤：查看一个词的完整信息。

交互：点击单词列表某一行，从右侧滑出抽屉。

```text
┌──────────────────────────────┐
│ suitcase                  ×  │
│                              │
│ 行李箱；旅行箱                │
│                              │
│ Example                      │
│ My suitcase is too heavy.    │
│                              │
│ 记忆提示                      │
│ 可以和 luggage 一起记忆       │
│                              │
│ 掌握度 40%                   │
│ [生成图片] [删除单词]          │
└──────────────────────────────┘
```

保留原功能：

- 单词释义
- 例句
- note
- 掌握状态
- Pexels 配图
- 删除单词

可以删减或弱化：

- 原来从网格跳到详情页的整页切换，建议改为 Drawer，因为用户是在“管理词表”，不应该频繁丢失列表上下文。

### 4. PDF 提取生词弹窗

对应步骤：用户上传 PDF 后，从资料中提取重点词。

建议位置：词表工作台右侧 `资料导入` 模块。

交互：

- 上传 PDF
- 显示已上传文件列表
- 点击“提取生词”
- 弹窗展示提取词
- 单个加入 / 全部加入当前词表

这保留原来的 RAG 上传、RAG stats、RAG clear、extract words，但把它从 Agent 中移到 Vocab，更符合人的理解：上传资料是为了扩充词库。

### 5. 图片识词面板

对应步骤：从图片中发现可学习单词。

建议位置：词表工作台右侧 `图片识词` 模块，或者作为一个弹窗。

保留原功能：

- 上传图片
- 本地 COCO-SSD 检测
- 悬停显示英文物体名
- 点击加入当前词表
- 调用 AI 补全释义

这个功能很适合 HCI 展示，但不适合作为主导航。放在词表工作台里会自然很多。

## 流程三：沉浸式学习与测验流程

目标：把原来的 Learn、Quiz、语音 Agent、PDF 问答重新组织成“选择学习方式 → 沉浸练习 → 即时反馈”。

入口：左侧导航 `沉浸学习 Study`。

### 1. 学习集线器页 Study Hub

对应步骤：选择今天学哪个词表、用什么方式学。

页面布局：

```text
顶部：
今天想练什么？
目标词表：[旅行文化 v]

主体入口：
┌──────────────┐ ┌──────────────┐
│ 词义速记      │ │ AI 短文阅读    │
│ 翻卡片记单词  │ │ 在语境里理解词 │
└──────────────┘ └──────────────┘

┌──────────────┐ ┌──────────────┐
│ 混合测验      │ │ 场景口语陪练   │
│ 词义/拼写/完形 │ │ 和 AI 角色对话 │
└──────────────┘ └──────────────┘

辅助：
[资料问答]  基于已上传 PDF 提问
```

这里我建议对 Gemini 的三个入口稍作调整，因为项目实际已经有这些能力：

1. **词义速记**：对应原 Flashcard
2. **AI 短文阅读**：对应原 Reading
3. **混合测验**：对应原 Quiz，包含词义、拼写、完形
4. **场景口语陪练**：对应原 Agent 语音对话
5. **资料问答**：对应原 RAG Chat，但作为辅助学习工具，不作为主入口

这样既不丢原功能，也不显得乱。

- 本轮完成页

- 不需要右侧 summary 常驻，可以改成顶部进度条。

## 流程四：全局反馈与复盘流程

这里我建议拆成两个页面：`Dashboard` 和 `Progress`。Gemini 把它们合并成个人数据仪表盘也可以，但结合项目实际，我建议职责分开：

- Dashboard：今天应该做什么
- Progress：长期学得怎么样

### 1. 仪表盘 Dashboard

对应步骤：用户打开软件后的第一眼。

它替代原来的 Overview。

页面布局：

```text
顶部：
早上好，今天继续练 10 分钟吧

核心指标：
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 总单词    │ │ 已掌握    │ │ 待复习    │

│ 旅行文化 有 6 个低分词需要复习       │
│ [开启今日专属复习]                  │
└────────────────────────────────────┘

最近学习：
最近添加的单词 / 最近练习记录
```

保留原功能：

- 平均掌握度
- 已掌握/总词数
- 最近单词入口
- 点击单词进入词表详情

建议新增轻量逻辑：

- 根据低分词自动生成“今日复习”入口。
- 点击后进入 Study 的混合测验或卡片练习，目标词表默认选低分词最多的词表。

```text
学习报告
```

保留原功能：

- 词表平均掌握度排行
- 薄弱单词
- 已掌握单词
- 今日次数、本月解决、连续天数

建议改动：

- 原来 Progress 三栏加热力图可以保留，但视觉上应该更像报告页，而不是统计组件堆叠。
- 每个薄弱单词可以点击进入该单词详情抽屉，或者一键加入今日复习。

## 重新组织后的用户心智模型

最后产品应该给用户的感觉是：

```text
第一次打开：
快速上手 → 配置模型 → 进入仪表盘

想准备学习内容：
我的词库 → 创建词表 → 手动加词 / AI 发现 / PDF 提取 / 图片识词

想开始学习：
沉浸学习 → 选择词表 → 卡片 / 阅读 / 测验 / 口语陪练

想知道学得怎么样：
学习报告 → 看薄弱词 → 一键进入今日复习

想调整系统：
系统设置 → API Key / 模型 / 数据管理
```

这个版本基本保留了原项目的亮点功能，但把它们从“开发者视角的功能堆叠”改成了“学习者视角的任务路径”。对 HCI 课程展示来说，叙事也会更清楚：WordForge 不是一个有很多按钮的工具，而是一个从词汇收集、语境学习、主动测验到反馈复盘的完整学习闭环。
